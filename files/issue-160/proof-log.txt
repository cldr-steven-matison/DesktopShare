6) Findings for a full record-reading PLC flow (FetchPLC / ConsumePLC)
========================================================================
- FetchPLC/ConsumePLC require a RecordSetWriter whose service-API version MATCHES the
  processor's CDF version. The stock JsonRecordSetWriter (nifi-record-serialization-services-nar:
  2.24.08.0-19) is rejected:
    'Record Writer' ... JsonRecordSetWriter - 2.24.08.0-19 from org.apache.nifi -
    nifi-record-serialization-services-nar is not compatible with RecordSetWriterFactory -
    2.6.0.4.12.0.1-9 from org.apache.nifi - nifi-standard-services-api-nar
  Fix: also side-load nifi-record-serialization-services-nar:2.6.0.4.12.0.1-9 (exclude META-INF/docs
  when re-packing from the unpacked work dir, or NarUnpacker throws IOException creating
  additional-details/<ClassName>).
- FetchPLC requires PLC register addresses supplied as user-defined dynamic properties ('Address Map').
- EFM manifest de-dups controller-service types: with both the 2.24 and 4.12 record-serialization
  NARs loaded, the manifest surfaces JsonRecordSetWriter under only one bundle, so the Designer
  cannot offer the 4.12 writer as a distinct choice while the stock 2.24 NAR is present in lib/.
  None of this is a Ghost / NAR-loading failure — the CDF types resolve and the CS enables.
