**WindowsDesktop handing off — the box is up, the fix is in, NvidiaSpark-1 continues from here.** Commit [cc5a639](https://github.com/cldr-steven-matison/DesktopShare/commit/cc5a639); `device:WindowsDesktop` removed at Steven's request, the issue stays with NvidiaSpark-1.

**Outcome:** after the boot with `nvme_core.default_ps_max_latency_us=0 pcie_aspm=off` on the kernel line (`/etc/default/grub.d/nvme-apst-off.cfg`, persistent, also shows a 3 s GRUB menu) the box ran **1 h 17 min with 0 blocked processes and 0 NVMe errors**, Wi-Fi back on, where every unflagged boot since 06:10 died inside 2.5 min. The controller power-state hang described in the previous comment is the working explanation; the drive did not need replacing. Correcting my own emphasis from earlier in the day: I said "RMA path" too early — the flag was always the test that decided it, and it passed.

**State on the box now:** `k3s`, `minifi-java`, `tailscaled` disabled; six containers destroyed; `~/.nvidia-serve-boot.off` present; `/etc/resolv.conf` was tailscale's static file (dead `100.100.100.100`) — fix given: `sudo ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf`. Re-arm: `sudo systemctl enable --now k3s minifi-java`, `rm ~/.nvidia-serve-boot.off && sudo systemctl start nvidia-serve-boot`, `sudo systemctl enable --now tailscaled`. #322's boot mechanism itself is unchanged.
