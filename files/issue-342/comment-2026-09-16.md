### Blocked — REST catalog not reachable from the box under the corp VPN
The box egresses on **`165.1.200.190`** (corp VPN full tunnel, `tun0`, from the #347 AWC/goes01 work). The Knox SG allows only **`179.64.39.45/32`** on 443 (the home IP). Direct proof:
```
curl --connect-timeout 8 https://srm-iceberg-aw-dl-gateway.../   → http_code=000, timeout (exit 28)
```
DNS resolves the gateway; the SG drops the packet. So the §3.3 read paths (InvokeHTTP + Knox OAuth2, `GetIceberg`, `QueryIceberg`) cannot be validated from `spark-dd06` while the VPN is up. This is a posture conflict on one box:
- **VPN up** (needed for goes01 / #343): egress `165.1.200.190`, not in the SG → catalog blocked.
- **VPN down**: egress reverts to the home IP already in the SG, but goes01 is lost.

No SG or VPN change was made — both are live-infra changes and whitelisting the shared corp-VPN `/32` is the wrong fix. **Needs Steven's call:** drop the VPN for a Public Cloud validation window, or add a stable box egress `/32` to the Knox SG.
