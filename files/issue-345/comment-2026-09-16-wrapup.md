**Three deploy-shape defects found and fixed on the running cluster, all now in the template**
1. Edit 10, ZooKeeper `zookeeper_enable_client_port: true`. AutoTLS + `enableSecurity` make ZK TLS-only (`clientPort=0`); the CFM 4.10 NiFi CSD pre-checks the quorum with a plaintext `zkCli.sh` on 2181 and exits 1. Evidence: [nifi-first-start-failure.txt](https://github.com/cldr-steven-matison/DesktopShare/blob/main/files/issue-345/nifi-first-start-failure.txt).
2. Edit 11, HDFS `core_site_safety_valve` → `hadoop.security.crypto.codec.classes.aes.ctr.nopadding = JceAesCtrCryptoCodec`. With `dfs.encrypt.data.transfer=true`, NiFi's first HDFS write (Ranger audit) crashed all four JVMs with `SIGSEGV` in `libcrypto.so.3` `ENGINE_get_cipher`: the `libhadoop` bundled in `nifi-ranger-nar-2.3.0.4.10.0.0-154.nar` vs the AMI's `openssl-libs-3.5.8-1.el9_8` (2026-08-28). CDH's own native lib was fine (Hive's encrypted writes worked). Evidence: [nifi-crash-openssl.txt](https://github.com/cldr-steven-matison/DesktopShare/blob/main/files/issue-345/nifi-crash-openssl.txt).
3. NiFi login: the CSD grants Ranger policies to user/group `nifi` only; `admin` gets 403. Added `admin` to every NiFi and Registry policy plus four process-group policies: [ranger-nifi-admin-grant.txt](https://github.com/cldr-steven-matison/DesktopShare/blob/main/files/issue-345/ranger-nifi-admin-grant.txt). Runbook §4 documents the FreeIPA-group alternative.

Same failure signature as the Mac's 09-15 run: `Invalid domain <master>.cldr.internal` on all three SCMs, primordial SCM certs with an IP-only SAN, master-02/03 unable to fetch a signed cert, Ratis `No name matching … SNIHostName` ×260, ring never forms; CM First Run fails on `0 Ozone Manager roles running`. But `DomainValidator` from the parcel's own commons-validator 1.10.1 rejects every `*.cldr.internal` name, `steven-ce-…` included, so the IP-only SAN was present on the earlier successful builds too; the TLD is not the discriminator. What decides whether the SCM ring survives it is still unknown (CM here is `7.13.2.10000-82229633`, Ozone `2.2.0.7.3.2.10000-317`). The domain change is a candidate, not a confirmed fix.
