Local AI — the knowledge base is live and the offload scoreboard has twelve readings (#240; #294 closed 2026-09-10 at 7.97 % generation share, the L2 soak gate accepted as not met). >
> **What is still open.** The in-NiFi Iceberg REST read from the box's CFM NiFi (`InvokeHTTP` + OAuth2, `GetIceberg`, `QueryIceberg`) is [#355](https://github.com/cldr-steven-matison/DesktopShare/issues/355). Cloudera AI Inference on AWC is blocked on a UI model deployment that fails with an AI Registry 503; its auth is solved ([#351](https://github.com/cldr-steven-matison/DesktopShare/issues/351)). The Trino catalog add on AWC waits on a GOES-team admin action ([#284](https://github.com/cldr-steven-matison/DesktopShare/issues/284)). The CE Base cluster from 2026-09-16 is still running (~$2/h); its teardown is [#357](https://github.com/cldr-steven-matison/DesktopShare/issues/357) and the clean end-to-end redeploy from the box is [#358](https://github.com/cldr-steven-matison/DesktopShare/issues/358). Cloudera AI on AWS (Ch5, Ch21) and the same-code arc (Ch24) are documented and design-accepted, not field-run. Cloudera AI on Data Services (Ch23) is **blocked — no test environment**; multi-Spark scale-out (Ch26) is gated on hardware. The H5 KB-validator soak has no verdict because the validator writes no ledger. Permanent homes for the scripts and exports attached to issues are decided in [#359](https://github.com/cldr-steven-matison/DesktopShare/issues/359). The Spark RAPIDS job on CDE waits on a GPU node group (`MaxVCAvailableGPU 0`) and Spark on Base has no CDS GPU path for 7.3.2.
>
> **The Cloudera coverage is two scopes.** Part VI covers using the DGX Spark with the Cloudera **platform** form factors (CDP Base CE on AWS, CDP Public Cloud on AWS, Cloudera AWC on AWS). Part VII covers the DGX Spark with **Cloudera AI** as a form factor in its own right (Cloudera AI on AWS, on AWC, and on Data Services), ending in the same-code-N-backends arc. RAPIDS is not a chapter of its own; it is the Cloudera AI on AWC chapter's workload (Ch22), because the AWC Workbench is the one Cloudera AI surface the box has run against.
>
> **Authoring rule for every chapter.** Write for a developer following the steps: plain facts, the shortest path to the goal. No war-story — the hurdles, dead ends, and decision history stay in the source docs and issues, not the guide. Do not mirror the EFM guide's phrasing or section structure; this guide's only likeness to that one is breadth and depth.

The DGX Spark is documented as a personal AI supercomputer and as nothing else. What is missing — and what this guide is for — is the box as a node in a working Cloudera platform: inference endpoint for NiFi and Flink, Kubernetes host for Cloudera Streaming Operators on Arm, EFM-managed edge agent, home of a local knowledge base for Claude Code, and the desk-side prototype that promotes unchanged into Cloudera AI on AWS.

**Naming rule (every chapter, every doc):** *DGX Spark* is the NVIDIA box; *Apache Spark* is the engine RAPIDS accelerates. Never bare "Spark" in a Cloudera-integration sentence.
