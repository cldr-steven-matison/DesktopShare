# CDP CLI + AWS SSO — new-device setup

Everything needed to bring CDP CLI and AWS access up on a fresh device against the Cloudera
tenant. It's a config + auth reference — the tools are assumed installed, and no secret ever
lands in this file. The two credential stores (`~/.cdp/credentials`, the SSO token caches) are
generated by login on the device and stay off git.

The scattered version of this lives across `cloudera-iceberg-rest-catalog-aws-plan.md`; this is
the one page to copy onto the next machine.

## Prerequisites (already done on your device)

- **AWS CLI v2** — `aws --version` should read `aws-cli/2.x`. v1 does not do SSO the same way.
- **CDP CLI** — installed in a venv here (`~/.venvs/cdpcli/`); `cdp --version` works once it's on `$PATH`:
  ```bash
  export PATH="$HOME/.venvs/cdpcli/bin:$PATH"
  ```

## 1. `~/.aws/config` — copy this verbatim

This is plain configuration, not a credential — it's safe to hand-copy to the new device. It
defines the shared SSO session and the `cldr-se` profile (role `cldr_poweruser`, workload region
`us-east-2`).

```ini
[sso-session Cloudera-Main-SSO]
sso_start_url = https://d-90677cc532.awsapps.com/start#/
sso_region = us-east-1
sso_registration_scopes = sso:account:access

[default]
region = us-east-1
output = json
sso_session = Cloudera-Main-SSO

[profile cldr-se]
sso_session = Cloudera-Main-SSO
sso_account_id = 007856030109
sso_role_name = cldr_poweruser
region = us-east-2
output = json
```

If you'd rather build it interactively instead of pasting, `aws configure sso` walks the same
fields — point it at the start URL and `us-east-1`, pick the `cldr_poweruser` role, name the
profile `cldr-se`.

## 2. `~/.cdp/config` — one line

```ini
[default]
cdp_region = us-west-1
```

## 3. Log in (run these yourself — they open a browser)

```bash
export AWS_PROFILE=cldr-se
aws sso login --profile cldr-se     # browser device-auth; writes ~/.aws/sso/cache/*.json
cdp configure                       # paste a fresh CDP API access key → ~/.cdp/credentials
```

`cdp configure` prompts for **CDP Access Key ID** and **CDP Private Key** — generate a new pair
in the Cloudera control plane (Management Console → your user → *Generate Access Key*). Don't
reuse an old device's key blindly; a key can be deleted control-plane-side and then every call
returns `NOT_FOUND` on `get-user`.

## 4. Verify

```bash
export AWS_PROFILE=cldr-se
aws sts get-caller-identity          # AWS SSO good → returns the assumed cldr_poweruser ARN
cdp iam get-user                     # CDP good → returns your CDP user
```

## Re-login cadence

The SSO token and the CDP session both expire overnight. When AWS calls start failing with an
expired-token error, or CDP calls `401`, just re-run the login — the config from steps 1–2 stays put:

```bash
aws sso login --profile cldr-se
# cdp configure only if the API key itself was rotated/deleted, not on normal expiry
```

## What NOT to commit

These are per-device and secret — they're created by the login steps above and must never be
copied to git or pasted into a session:

- `~/.cdp/credentials` — the CDP API access key + private key
- `~/.aws/sso/cache/*.json` and `~/.aws/cli/cache/*` — live SSO/session tokens

Only `~/.aws/config` and `~/.cdp/config` (steps 1–2) are reproducible configuration.
